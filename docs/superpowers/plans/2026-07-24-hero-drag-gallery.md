# Hero Drag Gallery Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the homepage hero's abstract 3D shader background with `DragGallery` (the existing infinite drag-to-pan masonry wall), showing real case-study photography, safely above the fold.

**Architecture:** `HeroSection.tsx` renders `DragGallery` (curated cross-case-study Cloudinary IDs) in place of `HeroScene`, with a dark scrim between the gallery and the text layer. `DragGallery` gets three additive changes — `background` prop, `eagerCount` prop for LCP, and a touch-direction fix so vertical swipes scroll the page instead of getting captured as pan — that also improve its existing `/work/[slug]` usage. `HeroScene` and its unused three.js dependencies are deleted.

**Tech Stack:** Next.js 16 (App Router, `apps/atrium.website`), React 19, TypeScript, `next-cloudinary`, Bun (`bun:test`), Biome.

## Global Constraints

- All three new `DragGallery` props (`background`, `eagerCount`) are optional with defaults that preserve current `/work/[slug]` behavior exactly (`background = '#fff'`, `eagerCount = 0`).
- The touch-direction fix applies unconditionally to `DragGallery` (both call sites) — no prop gates it.
- No new npm dependencies. `three`, `@react-three/fiber`, `@react-three/drei`, `@types/three` are removed (confirmed zero other consumers repo-wide).
- `heroGalleryIds` draws only from already-synced `cloudinaryAssets` (via `study.galleryIds`, populated by the existing sync loop in `lib/work.ts`) — no new stock/placeholder URLs.
- Run all commands from `apps/atrium.website/` unless stated otherwise.

### Task 4: `DragGallery` — touch-direction fix (vertical scroll passthrough)

**Files:**
- Modify: `apps/atrium.website/components/work/DragGallery.tsx` (new ref, `handleTouchStart`, the touch `useEffect`, container `touchAction` style)

**Interfaces:**
- Consumes: `isDraggingRef`, `dragStart`, `positionStart`, `targetPositionRef`, `dragSensitivity`, `resumeAnimationRef` (all existing).
- Produces: no new public interface — internal behavior fix applied to both `/work/[slug]` and the hero.

- [ ] **Step 1: Add a direction-decision ref**

Near the other refs (after `const positionStart = useRef({ x: 0, y: 0 })`), add:

```ts
  const touchDirectionRef = useRef<'pan' | 'scroll' | null>(null)
```

- [ ] **Step 2: Reset it on touch start**

Change `handleTouchStart`:

```ts
  const handleTouchStart = useCallback((e: React.TouchEvent) => {
    const t = e.touches[0]
    if (!t) return
    isDraggingRef.current = true
    touchDirectionRef.current = null
    dragStart.current = { x: t.clientX, y: t.clientY }
    positionStart.current = { ...targetPositionRef.current }
  }, [])
```

- [ ] **Step 3: Decide direction on first move, gate the pan logic**

Change the touch `useEffect`'s `onMove` and `onEnd`:

```ts
  useEffect(() => {
    const el = containerRef.current
    if (!el) return
    const onMove = (e: TouchEvent) => {
      if (!isDraggingRef.current) return
      const t = e.touches[0]
      if (!t) return

      if (touchDirectionRef.current === null) {
        const dx = t.clientX - dragStart.current.x
        const dy = t.clientY - dragStart.current.y
        if (Math.abs(dx) < 4 && Math.abs(dy) < 4) return
        touchDirectionRef.current = Math.abs(dx) > Math.abs(dy) ? 'pan' : 'scroll'
        if (touchDirectionRef.current === 'scroll') {
          isDraggingRef.current = false
          return
        }
      }
      if (touchDirectionRef.current !== 'pan') return

      e.preventDefault()
      targetPositionRef.current = {
        x: positionStart.current.x + (t.clientX - dragStart.current.x) * dragSensitivity,
        y: positionStart.current.y + (t.clientY - dragStart.current.y) * dragSensitivity,
      }
      resumeAnimationRef.current()
    }
    const onEnd = () => {
      isDraggingRef.current = false
      touchDirectionRef.current = null
    }
    el.addEventListener('touchmove', onMove, { passive: false })
    el.addEventListener('touchend', onEnd)
    return () => {
      el.removeEventListener('touchmove', onMove)
      el.removeEventListener('touchend', onEnd)
    }
  }, [dragSensitivity])
```

- [ ] **Step 4: Let the browser handle vertical scroll natively**

In the container style (same block touched in Task 2), change:

```ts
        touchAction: 'pan-y',
```

(was `'none'`). This tells the browser to natively handle vertical touch scrolling and leave horizontal gestures to our JS `preventDefault()` — the standard pattern for a horizontal-drag surface embedded in a vertically-scrolling page.
